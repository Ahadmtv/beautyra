# Backend gaps

Gaps between the frontend requirements and `openapi.yaml`. No endpoints are invented; each gap needs a backend decision before the matching adapter is replaced. Affected code is marked `TODO(backend)`.

1. **Authentication**: No login, logout, refresh, or current-user endpoint exists. `/login`, the httpOnly session cookie (read by `apiFetch` with `auth: true`), and role-based routing (client, provider, admin) cannot be completed against the contract. Until the endpoints exist, `AUTH_PROVIDER=mock` issues unsigned development tokens (`src/lib/auth/providers/mock.ts`). The JWT claims are assumed to be `sub`, `role`, and `exp` (`src/lib/auth/claims.ts`), and the signature is not verified in the frontend.
2. **Public provider list and profile**: Only `GET /api/v1/services` is public. There is no public provider list or provider detail endpoint. Cards are built per service, so a provider with several services appears several times.
3. **Provider card fields**: Public service items do not include provider name, specialties, neighborhood, city, photo, rating, or review count. These fields come from `src/lib/api/mock/provider-meta.ts` behind `USE_MOCK_META=true`. With the flag off, the card uses the service name and leaves those fields empty.
4. **Service filters**: `GET /api/v1/services` accepts only `cursor` and `limit`. Specialty, city, neighborhood, and search filters are missing, and there is no city or specialty taxonomy endpoint. The home page filters the fetched page in memory (`src/lib/listing/filters.ts`) and uses hard-coded option lists (`src/config/messages.fa.ts`, `src/config/filter-options.ts`). Results are incomplete until the endpoint supports filtering.
5. **Zarinpal callback result**: `GET /api/v1/payments/zarinpal/callback` returns 204 with no body, so the return page has no data source. Polling `GET /api/v1/payments/{paymentID}` needs a payment ID that the callback does not supply.
6. **Admin provider list**: Admins can change a provider's verification status by ID, but there is no endpoint to list providers.
7. **Image upload**: Provider photos have no upload or media endpoint.
8. **Error code catalog**: Problem `code` values are not documented. Persian messages are mapped by HTTP status only (`src/lib/api/problem.ts`). Code-specific messages should be added once the catalog exists.
9. **Other services of a provider**: The public API has no endpoint that lists a provider's services, so the service detail page cannot show "other services" from the same provider. The section is omitted rather than faked (`src/app/services/[id]/page.tsx`). Item 2 also applies here.
10. **Provider time zone before availability**: `AvailabilityResponse.time_zone` is the only place the provider's zone is exposed, and it arrives only after the day's availability is requested. The booking page needs "today" in the provider's zone to build the date strip and validate `?date=`, so it uses `DEFAULT_PROVIDER_TIME_ZONE` (`src/config/booking.ts`, `Asia/Tehran`). Providers in other zones may see the wrong "today" until the zone is exposed on the service or provider.
